## 一、产品定位与核心目标

### 核心产品闭环（MVP 聚焦方向）
打造一款轻量级、零门槛的跨平台制谱工具，核心壁垒在于实现 **【简谱输入 → 自动转译五线谱 → 实时音频合成与逐音高亮同步播放】** 的完整闭环。优先满足音乐初学者、中小学音乐教师及扒谱/练琴爱好者的快速制谱与对照视听需求。

- **目标用户画像**：音乐零基础或初级学习者（需要简谱与五线谱对照识谱）、中小学/培训机构音乐教师（快速制作教学曲谱与伴奏）、短视频创作者与乐器爱好者。
- **核心差异化优势**：相比 MuseScore、Sibelius 等重型专业软件，摒弃繁琐的排版操作，主打“所输即所得、一键转译、实时试听、逐段高亮追踪”。

## 二、核心功能模块拆解（P0 级 MVP 需求）

| 功能模块 | 核心功能拆解 | 技术实现关键点 |
| :--- | :--- | :--- |
| **1. 简谱录入引擎** | • **定制虚拟输入面板**：提供数字 1–7、高低音点、升降号（`#` / `b`）、增时线（`-`）、减时线（下划线）、附点、休止符（`0`）、小节线。<br>• **基础谱面设置**：支持调号（`1=C` 至 `1=B`）、拍号（`2/4`、`3/4`、`4/4`、`6/8`）、速度（BPM）设定。<br>• **智能节奏校验**：自动生成小节线，实时校验每小节总时值是否溢出或不足并给出视觉提示。 | 设计统一的 **【结构化中间数据模型（JSON / MusicXML）】**，存储音符的绝对音高（MIDI Pitch）、相对唱名（Scale Degree）及标准时值（Ticks），避免单纯存储文本字符。 |
| **2. 简谱转五线谱（核心引擎）** | • **实时自动转译**：根据用户选定的调号与拍号，将简谱音符实时映射转换为标准五线谱音符。<br>• **专业记谱规则自动处理**：自动判断符干方向（三线以上朝下，三线以下朝上）、符尾自动连杠（八分/十六分音符按拍分组连接）、同小节临时升降号作用与还原规则。<br>• **双谱混排对照**：支持“五线谱 + 简谱”上下双行垂直对齐显示，支持切换单简谱、单五线谱或双谱对照模式。 | 前端渲染建议采用成熟开源乐谱引擎 **VexFlow** 或 **OpenSheetMusicDisplay（OSMD）**，基于底层统一数据模型直接渲染五线谱 SVG，大幅降低复杂连音线、谱号与调号排版开发成本。 |
| **3. 音频合成与同步追踪播放** | • **录入即时发声**：点击简谱数字或虚拟琴键录入时，实时播放对应音高音频，辅助听觉纠错。<br>• **全曲播放与控制**：支持播放、暂停、停止、从指定小节起播、循环播放及 `40–200 BPM` 实时变速。<br>• **逐段逐音同步高亮**：播放过程中，当前演奏的小节与具体音符在五线谱和简谱上同步高亮变色，并伴随播放指针游标平滑推进。<br>• **多音色与节拍器**：内置原声钢琴音色（可扩展吉他、弦乐、长笛等），内置节拍器开关。 | Web 端推荐 **Web Audio API** 或 **Tone.js**；移动端原生开发推荐接入 **SoundFont（.sf2）** 高质量钢琴采样音源库。播放调度采用高精度音频时钟（`AudioContext.currentTime`）驱动 UI 指针帧同步。 |

## 三、简谱转五线谱核心乐理映射规则（开发参考）

中国用户普遍习惯使用“首调唱名法（Movable Do）”阅读简谱，而五线谱采用“固定调记谱”。转谱引擎必须内置完整的调号映射与音高换算逻辑：

| 调号设定 | 五线谱谱号调号 | 简谱“1”对应五线谱音高 | 转译处理要点 |
| :--- | :--- | :--- | :--- |
| `1 = C`（C大调） | 无升降号 | 中央 C（`C4`，下加一线） | 基础基准映射，1-7 依次对应 `C4-B4`；高音点 `+12` 半音，低音点 `-12` 半音。 |
| `1 = G`（G大调） | 1 个升号（`#F`） | `G4`（第二线） | 谱首自动添加 `#F` 调号；简谱输入 `7` 时，五线谱自动落在 `F5` 位置（由调号决定升 F）。 |
| `1 = F`（F大调） | 1 个降号（`bB`） | `F4`（第一间） | 谱首自动添加 `bB` 调号；简谱输入 `4` 时，五线谱自动落在 `B4` 位置（由调号决定降 B）。 |
| `1 = D`（D大调） | 2 个升号（`#F, #C`） | `D4`（下加一间） | 谱首自动添加 `#F`、`#C`；所有音符整体上移大二度映射。 |
| `1 = bB`（降B大调） | 2 个降号（`bB, bE`） | `bB3` 或 `bB4` | 根据音域自动选择最佳八度位置渲染，减少过多加线。 |

### 时值与符尾换算规则
以四分音符为一拍（`1 拍 = 480 Ticks`）：
- **全音符**（`X - - -`）= `1920 Ticks`
- **二分音符**（`X -`）= `960 Ticks`
- **四分音符**（`X`）= `480 Ticks`
- **八分音符**（`X` 下加一横）= `240 Ticks`
- **十六分音符**（`X` 下加两横）= `120 Ticks`
- **附点音符**：在原时值基础上乘以 `1.5`

## 五、技术架构与开发避坑指南

1. **坚持“单一数据源（Single Source of Truth）”架构**：切勿分别维护“简谱字符串”和“五线谱对象”两套独立数据。底层应维护唯一一份标准化的乐谱抽象语法树（Score AST / JSON），前端编写“简谱渲染器”和“五线谱渲染器”两套视图组件，同时订阅这份数据源。这样任意一端修改音符，另一端会自动同步更新，播放高亮也绝对不会错位。
2. **音频播放与 UI 渲染解耦**：切勿使用 JavaScript 的 `setInterval` 或普通定时器来驱动音符播放，否则在页面切换或性能波动时会出现节奏忽快忽慢。应使用 Web Audio API 的硬件音频时钟（lookahead 预调度机制）触发发声，前端 UI 通过 `requestAnimationFrame` 读取当前音频播放进度来刷新高亮指针。
3. **移动端/小屏幕交互适配**：简谱输入涉及大量组合键（如“高音 + 升号 + 八分音符 + 附点”），建议将输入键盘设计为“状态切换式面板”（先选时值与升降号状态，再点数字 1-7 直接上屏），大幅提升单手录入效率。
