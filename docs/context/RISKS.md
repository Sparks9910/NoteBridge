## 二、已知技术与产品风险（来自需求大纲）

| 编号 | 风险描述 | 保护 / 缓解措施 |
| :--- | :--- | :--- |
| **R-01** | **简谱与五线谱数据不同步**：分别维护两套数据结构会导致修改与播放高亮错位 | 严格执行“单一数据源”原则，底层维护唯一 Score AST / JSON，双谱视图共同订阅（见 [AGENTS.md](../../AGENTS.md)） |
| **R-02** | **音频播放节奏漂移与卡顿**：使用 JS `setInterval` 等普通定时器驱动发声易受页面调度影响 | 使用 `AudioContext.currentTime` 硬件音频时钟做 lookahead 预调度，UI 通过 `requestAnimationFrame` 同步高亮 |
| **R-03** | **多调号与临时升降号乐理边界复杂**：首调唱名法转固定调涉及同小节还原、八度最优位置选择及连杠分组 | 开发前需针对 `1=C` 至 `1=B`、常见拍号及临时升降号编写完备的单元测试集（当前测试尚未建立） |
| **R-04** | **P2 阶段 OMR（光学乐谱识别）研发成本极高** | 已在需求大纲中明确排期至 P2 远期规划，届时优先评估成熟商业 SDK 或开源深度学习模型，避免拖慢 MVP 交付 |
